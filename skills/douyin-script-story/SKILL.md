# 故事型口播框架生成器（六步结构）

为「故事型 / 转化型」口播生成框架：先用成果和痛点抓住人，再用自身困境建立信任，
然后交付方法、收尾给记忆点。产出必须是一个已保存的 Markdown 文件。

## 适用场景与边界

- 适用：个人转变、训练营招募、发起挑战、经验复盘、带课/引流私域等需要**讲故事、
  建立信任、促成行动**的选题。
- 不适用：纯单点干货（如“什么是单点突破法”“知识缝接怎么做”），那类用
  douyin-script-outline，更短更利索。
- 冷启动期没有百万粉人设，观众对陌生人的故事耐心有限，因此框架要做减法，
  见下方各环节要求。

## 六步框架与各环节要求

1. **成果（0-2s 内，一句话）**：亮一个**具体、克制的小成果**，且必须**立刻接痛点和预告**，
   不能单独把成绩甩出来吊胃口。
   - 用真实、可验证的结果（如“用 28 天带 30 个人养成读书习惯”），不夸大、不吹；
     冷启动观众不认识你，成绩单独先抛会像吹牛、引发反感。
2. **痛点**：让目标人群立刻对号入座，场景要具体。
3. **解决方法预告**：明确“这条会给你什么”，给观众留下来的理由。
   - 成果 + 痛点 + 预告三步压进前 5 秒，组成加厚钩子。
4. **自身困境经历（控制在 10-15s）**：讲“我也踩过这个坑”，解决“你凭什么教我”，
   并和观众站在一起。快速讲“我当时怎样 -> 后来怎么变”，不长篇煽情、不诉苦。
5. **解决步骤（干货交付，撑收藏）**：只讲 1 个核心方法，拆成 2-3 小步，
   每步可照做；不要塞多个方法。
6. **金句总结（改成大白话）**：用一句朴实、好记的话收尾，给记忆点和转发理由。
   不硬憋文绉绉的金句，避免假大空和“AI 味”。

## 输出的 Markdown 结构

- **开头钩子（前 5 秒）**：把“成果 + 痛点 + 预告”合成的逐字开场，给 2 个备选并标出最推荐。
- **六步框架**：按上面六步逐段给内容——第 1-3 步给逐字开场；第 4 步给困境的
  关键节点关键词（不要写长故事）；第 5 步给 2-3 个可照做的步骤；第 6 步给一句大白话。
- **行动引导（CTA）**：明确希望观众做什么（评论区报名、私信、关注后续、加入训练营）。
- **思路与提醒**：为什么这么开场；困境段别煽情、别超时；整条控制在 80-90 秒，
  录完看时长、超了就删。

## 时长

- 目标 80-90 秒，比纯干货框架略长（要讲一个短故事），但不要超过 90 秒。
- 冷启动期观众耐心有限，困境段和步骤段是最容易讲超的地方，重点卡这两段。

## 如何选开头钩子

1. 先读 [references/story-patterns.md](./references/story-patterns.md) 的开头钩子库。
2. 判断本条属于“成果背书 / 个人转变 / 发起决定 / 时间节点 / 认知误区”中的哪一类，
   按库里的表格对号入座。
3. 从中挑**最合适的 2-3 个钩子**，逐个改写成贴合本条主题、能直接念的完整句子，
   放进 MD 供用户选其一，并标注最推荐的一个。
4. 悬念/情绪类钩子后面，第二句必须立刻进入“事情本身”，不能只卖关子。

## 保存

- **保存位置**：统一保存到工程根目录的 `口播脚本/` 目录
  （`D:\Data\AI\github\zhigao\my-vault\口播脚本\`）。目录不存在则创建。
- **文件名**：`YYYYMMDD-HHMMSS-主题.md`，时间精确到秒，主题取 4-15 个汉字、去掉标点虚词，
  与 `口播脚本/` 已有文件命名一致。
  示例：`20261013-172600-我决定发起28天挑战带30人养成读书习惯.md`。
- 同一主题再出优化版时，在主题后加 `_优化版`、`_精简版` 等后缀。
- 保存后通过 `present_files` 交付该文件，并在回复中用一句话给出最推荐的开场和六步要点。
