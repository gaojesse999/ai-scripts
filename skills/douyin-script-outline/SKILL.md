# 口播框架生成器（一句逐字 + 整篇大纲）

帮用户用最少的时间准备一条知识口播：**只把开头第一句逐字写定，其余全部给框架关键词**，
让用户脱稿自由发挥。产出必须是一个已保存的 Markdown 文件。

## 核心原则（务必遵守）

1. **只逐字写第一句。** 除开头第一句外，其他部分只给关键词、节点和思路，禁止扩写成逐字稿。
   用户的目标是省时间，逐字稿是明确要避免的。
2. **一条只讲一个点。** 主题若含多个点，帮用户挑最值得讲的 1 个，其余建议以后单独做。
3. **开头要具体、与“我”有关。** 12 字左右的痛点反问或反常识结论，不要寒暄、自我介绍、
   安抚铺垫（“先别灰心/这不是你的问题”）。
4. **必须给一个可照做的动作。** 明确“第一步做什么”，具体到能立刻执行（这是收藏的来源）。
5. **时长卡在 60-80 秒。** 框架按这个时长设计，提示用户讲完看时长、超了就删。
6. 语言自然接地气，不堆砌术语、不浮夸、不要“AI 味”。

## 输入

- 用户给的主题/主要内容（可能只有一句话，也可能列了几个点）。
- 信息不足时，只需确认“这条最想让观众记住/做到的是什么”，不要反复追问。
- 若主题过宽，自行收窄并说明，不必反复确认。

## 输出的 Markdown 结构

文件中包含以下各部分（保留标题，内容按主题填写）：

1. **开头第一句（逐字，给 2-3 个备选）**：每个 12 字左右，都是具体痛点反问或反常识结论；
   标注最推荐的一个。
2. **整篇口播框架**：
   - **0-2s 开头**：直接用上面选定的逐字句。
   - **2-5s 承接**：第二句给“高手怎么做 / 反常识 / 超预期”，写关键词，禁止安抚铺垫。
   - **中段（只讲这 1 个点）**：2-4 个推进节点，每个写关键词；建议“先给动作、再讲原理”，
     可用一个小例子或个人经历。
   - **给观众的 1 个动作**：第一步做什么，写成可照做的一句话/小清单。
   - **结尾**：利他钩子——“明天讲 X”或“留言/私信”，不要只说“关注我”。
3. **思路与提醒**：为什么这么开头；要避免的点（别铺垫、别贪多、别讲嗨了绕）；
   控时长 60-80 秒、录完看时长。

## 开头钩子公式与示例

不同类型主题（学习方法 / 习惯养成 / 行动拖延）的开头句式、好与坏的对比，
见 [references/hook-formulas.md](./references/hook-formulas.md)。生成开头时参考，
确保具体、不宽泛。

## 保存

- **保存位置**：统一保存到工程根目录的 `口播脚本/` 目录（即本工程
  `D:\Data\AI\github\zhigao\my-vault\口播脚本\`）。目录不存在则创建；用户明确指定其他位置时以用户为准。
- **文件名**：`YYYYMMDD-HHMMSS-主题.md`，时间用当前本地时间、精确到秒；主题取 4-15 个
  能概括内容的汉字，去掉标点和虚词。这与 `口播脚本/` 目录里已有文件的命名保持一致。
  示例：`20261013-172600-我决定发起28天挑战带30人养成读书习惯.md`、
  `20261010-174500-认知觉醒单点突破法.md`。
- 同一主题若后续再出优化版本，沿用 `口播脚本/` 现有习惯，在主题后加
  `_优化版`、`_精简版` 等后缀。
- 保存后通过 `present_files` 交付该文件，并在回复中用一句话给出最推荐的开头和框架要点。
