# 用匹配锚点把行为嵌入真实日程

## R — 原文（Reading）

> “生活中有3类常见的提示：人物提示、情境提示和行动提示。相比于人物提示和情境提示，行动提示的效果是最好的，我还给它取了另一个名字：锚点。”
>
> — B.J. 福格，第4章「提示」

> “确定锚点时有3个方面可以考量。匹配物理位置。匹配频率。匹配主题／目的。”
>
> — B.J. 福格，第4章「确定你的锚点」

> “寻找一个更精准的时刻——我称之为‘最后动作’，即锚点行为的最后一个动作。”
>
> — B.J. 福格，第4章「利用最后动作优化锚点」

> “如果习惯和锚点不能自然匹配，那你可以考虑替换一个更适合的习惯。”
>
> — B.J. 福格，第4章「用试验将锚点与黄金行为联系起来」

---

## I — 方法论骨架（Interpretation）

- 提示回答“现在为什么会开始”，不能由愿望、动机或偶然想起代替。
- 人物提示来自记忆或身体信号，情境提示来自通知、物品或外部事件，行动提示来自已经稳定发生的行为。
- 一次性任务可以使用合时的情境提示；对重复习惯，默认先在真实日程中寻找行动提示，而不是新增固定闹铃。
- 任何稳定行动都不自动成为好锚点；先检查它与新行为的地点、频率和主题是否匹配。
- 地点决定提示到达时能否就地行动，频率决定触发次数是否合适，主题关联则让行为序列更自然。
- “早餐后”“下班后”仍是时间范围，不是精确锚点；要继续观察到可看见、听见或感觉到的最后动作。
- 最终配方写成“在我完成〔最后动作〕之后，我会〔具体行为〕”，让先后关系可观察、可试验。
- 提示出现不代表行为必然可做；还要检查当时的工具、时间、权限、注意力和安全条件。
- 提示越多不一定越可靠；竞争性通知、便利贴和闹铃会让人迟钝并掩盖关键提示。
- 配方只是待验证假设：在真实机会中试运行；失败时只改锚点或行为之一，再测，不评价人格。

## A1 — 书中的应用（Past Application）

### 案例 1：刷牙后清洁一颗牙

- **问题**：福格多年无法稳定使用牙线，单靠“记得去做”没有形成可靠序列。
- **方法论的使用**：他把已经稳定发生的刷牙动作作为行动提示，把新行为设为只清洁一颗牙，并与合适牙线配合。
- **结论**：与口腔护理同地点、同主题的既有行动，比额外提醒更适合作为重复行为锚点。
- **结果**：两周多后，他经常清洁全部牙齿，并把习惯长期保持到写书时。

### 案例 2：用关水声替代“早餐后”

- **问题**：埃琳娜把擦台面安排在“吃完早餐、餐具放进水槽之后”，但这个时间范围太宽，行为仍不稳定。
- **方法论的使用**：她观察早餐收尾序列，把锚点收敛到“关掉水龙头”；动作和水流停止的声音都可直接感知。
- **结论**：锚点需要落到明确的最后动作，而不是依赖人判断“现在算不算饭后”。
- **结果**：擦台面成为稳定习惯，厨房整洁引发的家庭紧张也得到缓解。

### 案例 3：护士用工作动作提示喝水

- **问题**：护士在长轮班中常忘记喝水，泛化提醒难以贴合高压工作现场。
- **方法论的使用**：护士从真实工作日程中选择“把扩展坞插回电脑”等既有动作，再接上喝水行为。
- **结论**：工作锚点只有在地点、发生频率和当时可行动条件匹配时，才可能比固定时钟提醒可靠。
- **结果**：培训前后测显示减压习惯、压力掌控、韧性技巧和健康工作习惯等多项指标有统计显著提升；该群体结果不能单独证明某一配方的因果效果。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 已经选好一个重复行为，也已足够容易，但总在一天结束后才想起来。
2. 用户用“早餐后、下班后、压力大时”作提示，执行时点每天漂移。
3. 闹铃、通知或便利贴经常在无法行动时出现，或已经多到被自动忽略。
4. 用户有多个稳定日程可选，需要比较哪个锚点与新行为最匹配。
5. 用户要把个人、家庭或工作场景中的既有行动写成可试运行的习惯配方。

### 语言信号（用户的话里出现这些就应激活）

- “这个习惯应该接在哪个已有动作后面？”
- “我明明想做，但到晚上才想起来。”
- “‘吃完饭后’太模糊了，怎么找最后动作？”
- “提醒总在我没条件做的时候响。”
- “Help me anchor this habit.” / “Which prompt should I use?” / “What should come after I...?”

### 与相邻 skill 的区分

- 与 `fogg-select-golden-behavior` 的区别：后者决定“做哪个行为”；本 skill 只处理已选行为“由什么信号、在何时触发”。行为仍抽象或不匹配时先返回选择流程。
- 与 `fogg-simplify-action` 的区别：后者通过能力链和微小化决定“怎样让动作更容易”；本 skill 不在内部拆小行为，只检查提示到达时现有行为是否可执行。
- 与 `fogg-diagnose-map` 的区别：后者可诊断失败来自提示、能力还是动机；本 skill 在提示已被确认需要设计或修正后，专门选择提示类型并构造锚点。
- 与 `fogg-reinforce-with-shine` 的组合：本 skill 决定行为前的启动信号，后者只在行为发生时或刚完成后检验自然、即时的成功感。
- 与 `fogg-support-consensual-change` 的组合：为他人或群体安排提示时，先由后者确认同意、权限与隐私边界，再共同选择不操控、可退出的锚点。
- 与日历或任务提醒的区别：一次性且已有明确日期的任务，通常直接设置一个合时的情境提示即可，无须强行寻找行动锚点。

## E — 可执行步骤（Execution）

当 skill 被激活后，agent 应按以下步骤执行：

1. **冻结待嵌入的行为**
   - 写明执行者、具体动作、预期频率、发生地点和所需工具；确认这是已选定且当前足够容易的行为。
   - **完成标准**：得到一句可观察行为，能明确判断一次是否完成，并写出期望频率与地点。
   - **判停条件**：若输入仍是“更健康、提高效率”等愿望，停止并转入 `fogg-select-golden-behavior`；若行为本身太难或步骤不清，停止并转入 `fogg-simplify-action`，不得用更多提醒掩盖能力问题。

2. **选择提示类型**
   - 比较三类提示：
     - **人物提示**：记忆、饥饿、疲劳等内部信号；除非身体信号本身稳定、明确且安全，不把“我会记得”当设计。
     - **情境提示**：日历、闹铃、通知、物品、他人或环境事件；优先用于一次性、低频或没有稳定行动可借用的任务。
     - **行动提示**：已经可靠发生的既有行动；重复习惯默认先从这里寻找锚点。
   - **完成标准**：明确选定一种提示类型，并用行为是一次性还是重复、所需频率及现实日程说明理由；重复行为若未选行动提示，必须记录行动提示为何不可用。
   - **判停条件**：若只是为日期明确的一次性任务设置提醒，到此停止锚点流程，交付一个在可行动时到达的情境提示；若只能依赖记忆且无可靠信号，停止并继续寻找情境或行动提示。

3. **用三维矩阵筛选行动锚点**
   - 从真实日程列出 3–5 个稳定候选行动，逐个检查：
     - **地点**：锚点结束时，是否已经在新行为发生地，工具是否触手可及？地点不匹配优先淘汰。
     - **频率**：锚点实际出现次数是否与目标频率一致？每日一次行为不绑定每周锚点，每周行为也不默认绑定每日锚点。
     - **主题／目的**：地点和频率都合格后，优先选择意义相近、联想自然的候选。
   - **完成标准**：形成候选矩阵，每项三维均有“匹配/不匹配/未知”及事实依据，并选出一个地点、频率合格且主题最自然的候选。
   - **判停条件**：存在“未知”时先观察真实日程，不凭想象选；没有候选通过地点和频率时，停止并重新寻找锚点，不因它稳定就强行配对。

4. **收敛到感官可识别的最后动作**
   - 像用显微镜一样观察候选行动的收尾，把“早餐后、洗漱后、到公司后”改成最后一个可看见、听见或感觉到的动作，如关掉水龙头、扣上杯盖或插回扩展坞。
   - 写出配方：`在我〔完成可感知的最后动作〕之后，我会〔具体行为〕。`
   - **完成标准**：第三方观察者能指出锚点发生的唯一时刻；配方不含“稍后、忙完、感觉到、饭后”等可漂移词。
   - **判停条件**：若候选没有稳定边界，或仍需靠主观判断“现在算不算”，淘汰该候选并返回步骤 3。

5. **通过能力、过载与安全闸门**
   - 在锚点真实出现的时点检查：是否有时间、工具、体力、脑力、权限和可中断空间立即执行；提示是否与现有通知、便利贴、闹铃或其他习惯竞争。
   - 检查锚点动作、新行为及自然会跟随的下一步是否安全，不得在驾驶、操作机器、用火用电、医疗操作或其他高风险时点引入分心、延迟或危险动作。
   - 优先删除、合并或遮蔽无关提示；不要把新增固定闹铃作为所有重复行为的默认补丁。
   - **完成标准**：明确记录“到达时可执行/不可执行”、主要竞争提示及处理方式，并把配方标为“可自行低风险试验”或“需专业/组织复核”。
   - **判停条件**：提示到达时能力为零、提示环境无法去噪、风险未受控或后续动作可能伤人时，停止试验；更换时点、锚点或交由合格负责人复核，不以习惯收益抵消安全要求。

6. **按 fm-01 试运行并单变量迭代**
   - 在 1–3 个真实机会中运行完整配方，逐次记录：锚点是否发生、是否被感知、当时能否行动、新行为是否紧接发生、是否被其他提示淹没，以及有无风险或干扰。
   - 失败时先根据记录提出一个假设：若锚点未被感知、边界模糊或三维错配，只改**锚点**并保持行为不变；若锚点已清楚到达但行为不能或不愿执行，只改**行为**，并保持锚点不变，必要时转交行为选择或简化流程。任何一轮都不得同时改两者。
   - **完成标准**：至少获得一次真实观察，并明确作出“保留配方 / 只换锚点再测 / 只换行为再测 / 转专业或组织处理”之一；每轮只有一个变量变化。
   - **判停条件**：出现危险、疼痛、工作中断、合规问题或明显恶化时立即停止；若同时改了锚点和行为，结果不可归因，本轮作废并恢复单变量测试；配方连续在真实机会中可靠发生后，本 skill 结束，不再追加提醒。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- 用户还没有选定具体行为，或只有愿望、成果和多个候选：先使用 `fogg-select-golden-behavior`。
- 行为已选但太难、太长、步骤不清或缺工具：先使用 `fogg-simplify-action`；提示不能弥补能力为零。
- 用户只需为日期明确的一次性事项设置日历提醒，且提醒时可以直接行动：使用简单情境提示即可，不必构造习惯锚点。
- 主要问题是动机冲突、奖励强化、坏习惯终止或稳定后的加量：本 skill 只设计提示，不越界代替其他流程。
- 驾驶、用火用电、药物、医疗、安全关键操作、照护、法律或合规场景中，锚点或后续行为可能分散注意、跳过必要步骤或降低标准时，不进行自助配方试验。
- 严重成瘾、自伤、进食障碍、创伤、躁郁症、重度抑郁、ADHD 等临床问题，不用锚点设计替代评估、治疗或合理便利。

### 作者在书中警告的失败模式

- **把提示交给运气**：计划只有做什么，没有可察觉、适时出现的启动信号。
- **依赖记忆**：把“到时候我会想起来”当人物提示，忙碌时便完全漏失。
- **错时提示**：固定闹铃在外出、会议或没有工具时出现，反复训练人关闭或忽略它。
- **提示过载**：用更多通知、红点和便利贴补救漏做，使重要提示被竞争信号淹没。
- **模糊锚点**：用“饭后、下班后、压力大时”等范围或状态，找不到唯一触发时刻。
- **三维错配**：锚点与行为地点不同、频率不等或主题割裂，只因锚点稳定就强行组合。
- **闹铃默认化**：为每个重复行为新增一个情境提醒，没有先检查既有行动能否成为锚点。

### 作者的盲点 / 证据局限

- 书中锚点效果主要来自作者、学员和项目参与者自述，缺少对不同提示类型的充分随机对照和长期比较；三维匹配应作为待验证启发式，而非普适定律。
- 轮班、照护、突发工作、残障和资源稀缺会让既有行动不稳定；此时没有可靠锚点可能是结构条件，不是个人不够认真。
- 现代设备的跨应用通知、推荐系统和多端红点比书中案例更密集，仅新增提示常会加重过载；必要时应先治理通知环境。
- 医院护士项目报告群体前后变化，但不能把结果单独归因于某个锚点配方，也不能用个人喝水习惯替代排班、软件和休息条件改革。

### 容易混淆的邻近方法论

- **选择行为不等于设计锚点**：先确定做什么，再决定由什么触发；换锚点不能修复错误行为选择。
- **简化行动不等于设计锚点**：前者降低动作门槛，后者定位启动时刻；提示出现时做不到，应返回能力设计。
- **稳定日程不等于好锚点**：必须同时通过地点、频率、主题和最后动作检查。
- **收到提示不等于有能力执行**：MAP 三要素仍须在同一时点成立。
- **行动提示优先不等于绝对排斥闹铃**：一次性或无稳定行动可借用时可用情境提示，但必须适时、可执行且不过载。
- **调整配方不等于同时重做一切**：为保留可归因性，每轮只更换锚点或行为之一。

## 相关 skills

- 本 skill 依赖 [`fogg-simplify-action`](../fogg-simplify-action/SKILL.md) 先把行为降到提示出现时确实能做的程度；能力为零时，增加再精确的提示也不能补救。
- 与 [`fogg-diagnose-map`](../fogg-diagnose-map/SKILL.md) 配合时，MAP 先确认提示是优先瓶颈，本 skill 再选择提示类型、三维匹配锚点并收敛到最后动作。
- 与 [`fogg-reinforce-with-shine`](../fogg-reinforce-with-shine/SKILL.md) 组成“锚点 → 行为 → 即时反馈”序列：本 skill 管行为前的启动时刻，后者检验行为后的真实成功感。
- 与 [`fogg-support-consensual-change`](../fogg-support-consensual-change/SKILL.md) 配合时，任何用于他人或群体的提示都必须共同选择、尊重隐私且允许拒绝，不能借锚点做秘密操控。
