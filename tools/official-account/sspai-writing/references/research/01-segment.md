## 1. 开头技巧

少数派开篇几乎不做冗长铺垫，核心是**快速建立"与你相关"的场景或痛点**，几种典型套路：

### （1）用「痛点提问 / 生活场景」直接切入（最常见）

> 「每到各大购物季来临要买东西，家人总会问我：『今天该刷哪张卡？』」——（C，WiseSwipe）

> 「我最初想做 Coday，是因为我发现自己很难回答一个简单问题：一件东西到底买得值不值？」——（C，Coday）

### （2）承接系列/旧文，建立连续感与专业背书

> 「在之前的文章 macOS 的『预览』有几种用法？ 中，我们关注了 macOS 当中的拥有着十八般武艺的『预览.app』，在这篇文章里我们继续沿着类似思路继续前行。」——（A）

### （3）"找不到满意的工具，于是自己做"——开发者自荐的经典叙事母题

> 「说起记账和资产管理，市面上其实不缺工具，但用了一圈下来，总觉得差点意思 …… 找了一圈没找到满意的，行吧，那就自己做一个。于是就有了 知盈 iAssets 。」——（C，知盈）

### （4）先给读者一个"读完能获得什么"的承诺（教程类）

> 「通过本文，你可以了解到 Option 相关的操作，进而加快自己电脑操作的速度，让自己表现出一副高手的样子。」——（A）

### （5）一句话点题式产品引入（短文）

> 「Raycast 团队推出了一款新应用 —— Glaze，专注于通过 AI 来生成 Mac 应用。」——（B）

**小结**：开头 = 场景/痛点 + 与"你"的关系，很少空谈背景。教程类会补一句"读完你能获得什么"。

## 2. 句式与节奏

- **长短句交错**：解释原理用长句（带括号补充、破折号插入），下结论/给操作用短句。
  > 「这里的『交易日』到『还款日』之间的时间差，就是信用卡的『免息期』。」——（C）短句定义。
  > 「如果你有多张信用卡，由于每一张卡片的账单日和还款日规则不同，即使是同一天刷卡，它们的免息期当然也会不一样。」——（C）长句铺陈。

- **第一人称程度高**：大量「我」「我们」「你」。教程用「我们」拉近协作感，测评/自荐用「我」讲个人动机。
  > 「首先也是我最常用的办法……」——（A）
  > 「当我们谈到 macOS 的时候，总是会下意识地把它与 Windows 进行对比。」——（A）

- **段落短**：多为 1–3 句一段，一个信息点一段，几乎没有超长段落，便于手机端阅读。

- **口语插入语调节节奏**：「老实说」「说白了」「行吧」「不中！」等，让长解释不枯燥。
  > 「善于感知万物的我们总会在某个时间点感受一些事物的细微差异：上浮一点，多了；下调一点，少了。中，不中！系统似乎实现不了。」——（A）

## 3. 文章结构

### 小标题与层级符号 `▍`
教程/测评用 `▍` 作为一级功能分区标题，下面再用不带符号的短行做二级小标题。

> 「▍ Option + 访达」→ 下设「路径显示与跳转」「文件复制」「快速复制」……——（A）
> 「▍ 它有什么功能？」「▍ 100% 本地应用，不收集任何数据」「▍ App Icon 设计分享 🎨」「▍ 未来规划 Roadmap」——（C，WiseSwipe）
> 「▍ 知盈是什么」「▍ 首页看板 — 你的资产仪表盘」「▍ 账户管理 — 30+ 种类型全覆盖」——（C，知盈）

- 小标题常用 `—`（破折号）带一句副标题概括，形成"标题 — 卖点"结构：「首页看板 — 你的资产仪表盘」「多账本 — 场景隔离，互不干扰」。（C，知盈）

### 分点方式
- 功能罗列用「短标签：+ 解释」的分层块（冒号 + 换行 + 展开），而非纯 bullet。
  > 「资产总览卡：/ 总资产、总负债、净资产三个核心数字……」——（C，知盈）
  > 「桌面小组件：/ 款式比较多，有大、中、小三种尺寸……」——（C，WiseSwipe）

### 结尾套路
- **教程用"以上就是…"式收束 + 邀请互动**：
  > 「以上就是本文梳理的 Option 相关的功能了，但是显然玩法并不止这么多。macOS 上更多的功能与技巧等着你来探索。希望文中的这些小技巧能够帮助到你，也欢迎留言一起分享更多的小技巧。」——（A）
- **产品测评用"总的来说 / 最后"总评 + 试用邀请**：
  > 「总的来说，Glaze 在用户操作体验和最终交付效果上都做得相当不错……对有团队应用开发需求的群体来说是一个不错的选择。」——（B）
  > 「如果你也和我一样，拥有多张信用卡……不妨试试『慧刷 WiseSwipe』。希望它可以帮到你，也欢迎随时在 App Store 和文章评论中提意见和反馈～」——（C，WiseSwipe）
- **常带"彩蛋/One more thing"式补充**：
  > 「One more thing：本文所有的配图都使用我通过 Glaze 打造的 Image Joiner 拼接生成，欢迎大家试用。」——（B）

## 4. 中英文混排规范

- **专有名词/产品名保留英文**：macOS、Finder、Safari、Raycast、Glaze、iCloud、Face ID、APFS、GUI，产品名多为「中文名 + 英文名」并列。
  > 「『慧刷 WiseSwipe』」「知盈（海外版叫 iAssets）」——（C）

- **中英文之间加空格**（数字、英文词与中文之间统一空格）：
  > 「重量仅 168g」「你会获得 120 个 credits」「229 个 Swift 文件」「内置了 392 个银行 Logo」——（B/C）

- **快捷键写法**：英文键名 + 对应符号图标，符号紧跟其后；组合键用 `+` 连接。
  > 「Command ⌘」「Option ⌥」——（A）
  > 「Command + Option + V」「Shift + Option + 音量 / 亮度」——（A）

- **术语首次出现给英文全称 + 缩写解释**：
  > 「GUI 是 Graphical User Interface 的缩写，即图形用户界面……」——（A）
  > 「复制（Duplicate）」「精确复制（Duplicate Exactly）」——（A）中文译名后括号补英文原词。

- **英文词直接当动词/名词嵌入句子**：「继续通过 Glaze 来 debug」「一键发布」「自动生成 tagline、full description、icon」——（B）

## 5. 标点与排版

- **书名号《》用于文章/作品名**：
  > 「在之前的文章《macOS 的『预览』有几种用法？》当中……」——（A）

- **直角引号「」为默认引号**（贯穿全文），强调词、界面文案、比喻都用「」：
  > 「身轻如燕」「门禁」「隐形资产」「钱袋子」「今日最佳」——（A/C）

- **加粗/强调**：语料中强调多靠「」直角引号与短句独立成段实现，而非大量 markdown 粗体；关键卖点常单独成行。

- **括号补充说明**（半角/全角混用，常放"顺带一提"的口语补充）：
  > 「（虽然说现在货币基金的收益也只有那么一点啦，单次看可能也就是毛毛雨，但积少成多，况且如果是大额消费，还是有差。）」——（C）
  > 「（如果卡片真的逾期了，我觉得还是先别看这个应用了，赶紧去还上要紧）」——（C）
  > 「（IT之家注：欧洲中期天气预报中心）」——（此为第 807 行后邻篇，本段不计入）

- **破折号 `——` / `—`** 用于引出结论、并列副标题或口语转折：
  > 「Option 所做的就和它图标 ⌥ 所展示的那样 —— 展示菜单和选项的另一面。」——（A）

- **Emoji 作分区/标签点缀**（尤其目录、卖点、短文）：
  > 「👛 WiseSwipe ：你的电子卡包 / 💰️ 知盈 ： 家庭资产管理 App / 🪙 Coday ……」——（C 目录）
  > 「✨ 低调的金属紫色 + 磨砂质感……🍃 弯头的工艺设计……💨 6 挡位风速可调」——（D）

## 6. 口语化 / 亲切感手法

- **直接与"你"对话**，把读者拉进场景：
  > 「如果你在访达中按住 Option + Shift，会发现菜单里的『复制』会变成『精确复制』……相信不少用了十几年 Mac 的人都没有见过它。」——（A）

- **"我们"制造同行感**（教程尤甚）：
  > 「在这里，通过『Option +』，我们可以看到一个『不一样的』macOS。」——（A）

- **口头禅/语气词**：「老实说」「说白了」「行吧」「不妨」「大家好呀」「啦」「～」。
  > 「老实说在刚刚上手 macOS 的时候，我还是挺怀念 Windows 上的资源管理器的。」——（A）
  > 「说白了，我就是想要一个 简单、好看、能把家里所有资产和负债一目了然展示出来 的工具。」——（C，知盈）
  > 「大家好呀，我是 Meng 小羽」——（C，知盈）

- **自嘲/玩笑式插话**，消解说教感：
  > 「这里抛砖引玉的举出几个栗子。」——（A）
  > 「强迫症患者表示很舒服。」——（C，知盈）

- **邀请互动收尾**：「欢迎留言」「欢迎在评论区告诉我」「欢迎随时……提意见和反馈～」。（A/C）

## 7. 实用主义导向（"实用 / 效率 / 值得"）

少数派的价值主张永远落在"对你有什么用、省了什么、值不值"：

- **强调效率提升**：
  > 「通过它，用户的操作将会更加地『身轻如燕』。」「进而加快自己电脑操作的速度」——（A）
  > 「这样就省掉了鼠标来回晃动找『×』的麻烦了。」——（A）

- **站在用户"值不值/划不划算"角度算账**：
  > 「卡片一多，每次都要自己去记账单日、还款日，再手动计算，时间成本和精力成本实在是不划算。所以这种事情还是得交给工具来做。」——（C，WiseSwipe）
  > 「买下来的那一刻消费并没有结束，真正的成本是在后面的使用周期里慢慢被理解的。」——（C，Coday）

- **诚实标注适用边界 / 不夸大**（增强可信度）：
  > 「对于绝大多数人来说，这个区别几乎没有影响。但如果这台 Mac 上有好几个多人账户……」——（A）
  > 「当然，这个数据仅供参考，不构成任何理财建议。」——（C，WiseSwipe）
  > 「需要注意的是你要确定要安装的 App 来自于可信来源，并且未遭篡改，否则可能会导致 macOS 和个人数据的安全问题。」——（A）

- **用"我为什么这么设计"讲价值取舍**（自荐文常见）：
  > 「在设计最初，我就认为这个工具最好是不打扰的，所以小组件功能十分必要。」——（C，WiseSwipe）
  > 「我比较在意付费边界，因为这类工具如果一开始就把核心记录能力锁起来，会很容易打断使用习惯。」——（C，Coday）

- **给出目标人群清单**，帮读者自我对号入座：
  > 「如果你有这些需求，可能会比较适合试试 Coday：想知道自己买过的东西是否真的被用起来；想用日均 / 次均成本来辅助判断『值不值』……」——（C，Coday）

## 8. 配图说明文字（图注）写法

图注紧跟在图片下方，**短、白描、说清"图里在看什么"**，常见三种：

- **纯功能标签式**（一个名词短语，句末常带句号）：
  > 「今日最佳刷卡推荐。」「刷卡模拟器。」「配置账单日、还款日规则。」「桌面小组件。」「锁屏小组件。」——（C，WiseSwipe）

- **对比说明式**（教程标志性写法，交代"按前/按后""左/右"）：
  > 「右键对比，左侧为未按 Option 键，右侧为按 Option 键」——（A）
  > 「按 Option 键前后对比，左侧为未按，右侧为按」——（A）
  > 「按 Option 键前后对比：左侧为未按，右侧按 Option 键后出现『强制退出』」——（A）

- **操作路径式**（把菜单点击路径写进图注）：
  > 「按 Option 键 > Safari 浏览器 > 清除历史记录但保留网站数据」——（A）
  > 「Option + 屏幕亮度键快速跳转设置」——（A）

## 9. 文末噪音清单（本段出现的"文末不需要的信息"模式）

以下模式在构建 Skill 时**应剔除**，均在本段语料中出现：

1. **文章头部元信息块**（每篇开头）：
   - `- 文章 ID: 3582870021-...`
   - `- 公众号 ID: MP_WXS_3582870021`
   - `- 发布时间: 2026-07-12 04:00:00`
   - `- 原文链接: https://mp.weixin.qq.com/s/...`
   - `- 摘要: ...`
2. **文末原文链接与追踪参数**（分行出现）：
   - `原文链接：`
   - `https://sspai.com/post/73385`
   - `?utm_source=wechat&utm_medium=social`
3. **作者署名块**：
   - `作者：`
   - `jijiali`（作者名单独成行）
4. **板块标题及其后图片**：
   - `/ 更多热门文章 /`
   - `/ 产品推荐 /`
   （其后紧跟的均为 banner 图片链接）
5. **全部图片 markdown**：`![图片](https://mmbiz.qpic.cn/...)` 及 `![图片](http://mmbiz.qpic.cn/...)`（含 `?wx_fmt=jpeg/webp/png/gif&from=appmsg`）。
6. **文章分隔线**：单独一行的 `---`。
7. **网页/弹窗残留 UI 文本**（抓取噪音，尤其短文末尾）：
   - `知道了` / `取消` / `允许`（反复出现）
   - `×` / `分析`
   - Glaze 篇末的 `知道了 取消 允许 …… × 分析`（B）
   - 风扇篇末同款残留（D）
8. **合集/自荐类附带的下载区碎片**（可视情况保留链接、剔除排版碎片）：
   - `🧑‍💻` / `bakamio` / `|  🤖 iOS` / `|` / `下载地址`（C 中每款 App 前的开发者信息块被抓取成散行）
   - `下载链接 🔗： https://apps.apple.com/...`、`官网：https://coday.cc` 等（属正文有用信息，但排版散乱需归并）
9. **编注块**（合集类会有，属平台声明，视用途保留或剔除）：
   > 「编注 ： 本期内容为少数派 Matrix 社区应用自荐文章合集……少数派仅对标题和排版略作修改。」——（C）
