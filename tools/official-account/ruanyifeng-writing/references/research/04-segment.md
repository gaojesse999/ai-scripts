## 1. 开头技巧

阮一峰的每周评论几乎不做铺垫，开头就把读者直接拽进场景或抛出判断。主要有四种范式：

**（A）"你还记得吗"式召唤共同记忆** —— 用第二人称拉近，制造"我们是同类人"的默契。

> "如果你在互联网行业足够久，大概会记得，以前有过一次 API 开放的浪潮。"
> ——《周刊#394：第二次 API 开放浪潮》

**（B）"我最近学到/看到"式的个人化引入** —— 以自己的第一手经历开场，显得亲切、不端着。

> "最近学到一个新词'脑腐'（brain rot）。"
> ——《周刊#393：脑腐状态》

> "我越来越觉得，AI 跟其他技术不一样，不仅带来技术变革，还会带来社会变革。"
> ——《周刊#391：AI 的贫富分化》

**（C）设问开场，直接把读者带入思考** —— 先问一个大问题，再回答。

> "如果现在做一个问卷调查，问大家'你觉得大模型是否具有智能？'／我相信，大多数人会是肯定的回答。"
> ——《周刊#390：没有语料，大模型就是智障》

> "怎么衡量大模型的能力？"
> ——《周刊#391·模型能力的一种衡量方法》

**（D）新闻钩子 + 悬念（多见于深度分析文）** —— 先点出事件的分量，勾起好奇心。

> "本周末，有一条最热闹的 AI 新闻，震动了太平洋两岸，连马斯克都关注了。"
> ——《扒一扒 Cursor 的"套壳"疑云》

## 2. 句式与节奏

**（1）短句为主，一句一个信息点，句子干净利落。** 他很少写从句套从句的长句，复杂内容用逗号断成小段推进：

> "它就是字面意思。有些人看上去是正常的，但是大脑已经变异了，有些部分腐烂了。"
> ——《周刊#393：脑腐状态》

**（2）段落极短，常常一两句就独立成段。** 这是阮一峰最鲜明的排版节奏，制造"呼吸感"和"层层推进感"：

> "但是，事情的发展跟预想完全相反。"（独立成段）
> ——《周刊#394：第二次 API 开放浪潮》

> "简单说，AI 会带来贫富分化。"（独立成段）
> ——《周刊#391：AI 的贫富分化》

**（3）口语化过渡词开头**："但是""于是""所以""这就是说""这意味着""总之"频繁充当段首，把逻辑关系摆在明面上，读者不用费劲。

> "自动化意味着 AI 必须能够调用其他平台，进而意味着，其他平台必须先开放自己的 API。"
> ——《周刊#394》

**（4）长短交错——观点句短，解释句稍长。** 先甩一句短判断，再用一个较长的句子补充因果：

> "但是，大模型不存在规模效应，模型的大规模生产需要更多的服务器，这并不会让单位成本降低，反而可能因为扩建机房，改造电路和水路，而变得更贵。"
> ——《周刊#391：AI 的贫富分化》

## 3. 论证结构（现象→观点→论据→收尾）

阮一峰的评论几乎都是标准的"倒漏斗"结构：**先给现象/新闻 → 提炼一句核心观点（常加粗）→ 用数据或类比做论据 → 用一句展望或反问收尾**。

**完整范例（《周刊#391：AI 的贫富分化》）：**

- 现象/反差铺垫：
> "其他技术实际上会消灭贫富分化，实现'消费者平等'，即穷人和富人消费的东西是一样的。比如，大家喝一样的可口可乐，用一样的苹果手机，开一样的特斯拉。"
- 观点（加粗独立）：
> "但是，AI 模型不是这样。**在大模型面前，穷人和富人是不平等的**。"
- 论据（现实+数字）：
> "现在就是如此了，最贵的 AI 编程套餐是 Claude Code 的 Max 套餐，月费200美元，很多人已经用不起了。OpenAI 曾经设想过月费2万美元的套餐……"
- 提炼因果：
> "这反映了一个简单的事实：**费用越贵，模型效果越好**。因为模型的效果与算力相关……"
- 开放式收尾（留一个悬念/另一种可能）：
> "可能吗？我不知道，感觉还是前一种情况更现实。"

**另一范例（《周刊#390：没有语料，大模型就是智障》）：** 提出常识判断 → 亮出反直觉观点 → 引一个实验做硬证据 → 用数字砸实 → 抛出新问题收尾。

> "但是，我们不要忘记真实情况，**大模型不是魔法，更不是具有自主智能的'硅基智能体'，而是基于统计规律的语言模型**，它的一切行为都基于数学计算。"
> "这五个大模型的平均答题正确率仅为3.8%，即 100道题可以答对3.8道。相比之下，它们处理 Python 问题的正确率可以达到90%。"

## 4. 口语化 / 亲切感手法

**（1）大量第二人称"你"，把说理变成对话。**

> "你有没有这个症状？如果有，就有'脑腐'的危险了。我感觉，我的大脑就有一点。"
> ——《周刊#393：脑腐状态》

**（2）主动暴露自身局限，显得诚恳不装。**

> "我不是版权专家，不能确定这种说法对不对，但是听上去有道理。"
> ——《周刊#393·权重有没有版权》

> "这些问题能识别出 AI 编程高手吗？我完全没有把握。"
> ——《周刊#389：未来如何招聘程序员》

**（3）口语感叹与拟声，像聊天一样。**

> "哦喔，就这样中招了，发布令牌一秒钟就泄漏了。"
> ——《周刊#392：axios 投毒与好莱坞式骗术》

> "大家一看：'哇塞，太神奇了！'"
> ——《TRAE 的 Linux 版来了》

**（4）直接向读者征询、发起互动。**

> "大家有好的面试问题吗？"
> ——《周刊#389：未来如何招聘程序员》

> "大家可以自己去问问大模型'计算结果有没有版权？'，看看大模型怎么回答。"
> ——《周刊#393·权重有没有版权》

**（5）加评论式感慨，带个人情绪。**

> "作假到这种程度，让人叹服。"
> "天哪，骗子从早到晚演了16天……这要是拍成电影，该有多动人。"
> ——《周刊#392：axios 投毒与好莱坞式骗术》

> "这么著名的软件，居然想出这种类似'开后门'的解法，而且对象是付钱给他的人，真让人无语。"
> ——《周刊#392·Adobe 修改 hosts 文件》

## 5. 金句与提炼

阮一峰擅长把一段分析压成一句可传播的判断句，常放在段末或独立成段，多数加粗。

> "AI 的最大价值不是内容生成，而是内容生成 + 自动化。"
> ——《周刊#394》

> "突然之间，API 不再是累赘，而是接入 AI 的必须条件。"
> ——《周刊#394》

> "凡是它能生成的东西，都将变得极大丰富。"
> ——《周刊#394·AI 是扩展神器》

> "没有语料，大模型就是智障"（直接用作标题的金句）
> ——《周刊#390》

> "网站开发有一条规则：客户端的每一个请求都不可信任，必须假定是恶意请求。以后，现实生活恐怕也是这样：每一个陌生人都不可信任，必须假定是恶意骗局。"
> ——《周刊#392：axios 投毒与好莱坞式骗术》

## 6. 用数字 / 对比 / 类比说话

**（1）用具体数字建立可信度和冲击力。**

> "一个函数就长达3,167行，包含486个判断分支和12层嵌套，入口文件 main.tsx 大小为 785 KB。"
> ——《周刊#393·科技动态·Claude Code 的源码真相》

> "整个字体仅占用350字节的内存……即使只有 16kB 内存的8位微控制器，也能完成字体渲染。"
> ——《周刊#394·图片·5x5 像素字体》

**（2）用对比拉开反差，突出观点。** "工业品 vs 大模型""穷人 vs 富人""以前 vs 现在"是他最常用的对照结构。

> "这跟工业品完全相反。工业品有规模效应，产量越高，单位成本越低……但是，大模型不存在规模效应。"
> ——《周刊#391：AI 的贫富分化》

**（3）用生活化类比解释抽象概念。** 把技术问题翻译成人人能懂的日常经验：

> "比如说，你写了一个程序，实现了一种更高效的根号2的算法。那么，这个程序是有版权的，但是计算结果根号2（1.414）是没有版权的。"
> ——《周刊#393·权重有没有版权》

> "这个攻击是有剧本的……完全是精准投放的'剧本杀'。"
> ——《周刊#392》

**（4）把趋势量化成"翻倍/速度"的直观表达。**

> "每7个月，大模型能够以50%成功率完成的任务，时间范围扩大一倍。"
> ——《周刊#391·模型能力的一种衡量方法》

> "可以看到，每过几个月，估值就会翻倍。这种火箭式的上升速度，需要有业绩支持。"
> ——《扒一扒 Cursor 的"套壳"疑云》

## 7. 标点与排版偏好

**（1）加粗提炼核心句。** 全段大量使用加粗（`**…**`），专门用于标记"要记住的那句话"：
> "**大模型的表现（智能程度）首先由训练材料决定**"（#390）
> "**面试各种编程细节意义不大了**"（#389）

**（2）括号补充说明/插话。** 括号既用于术语注释，也用于插入吐槽或旁白：
> "（半马的人类世界纪录是1小时02分52秒）"（#394，客观补充）
> "他也宁愿看几分钟的电影解说。"前后的口语插入（#393）
> "（空间太阳能？）"——用括号+问号表达自己的猜测和保留（#391）

**（3）中文顿号列举 + 省略号收尾**，营造"还有很多、不一一列举"的语感：
> "最顶级模型的服务——规划、咨询、生成内容、自动化……"（#391）
> "AI 可以把脑子里的一个想法，不断扩展出文档、代码、产品、发布会、就业……"（#394）

**（4）破折号做插入解释或转折。**
> "这五个大模型……让大模型使用五种小众的编程语言——Brainfuck、Befunge-98、Whitespace、Unlambda 和 Shakespeare——来编程解决各种问题。"（#390）

**（5）带圈数字/项目符号分点。** 需要并列列举时用"（1）（2）（3）"或"•"分点，结构清晰：
> "（1）这次开放的不仅是云服务……（2）这次的 API 不需要手动编程……（3）这次的 API 是消费者通过 AI 调用……"（#394）

**（6）引号标记新词/反讽词。** "脑腐""围墙花园""硅基智能体""剧本杀""访达小子"——给新概念或带态度的词加引号。

## 8. 深度分析 / 调查类文章的写法（以《扒一扒 Cursor 的"套壳"疑云》为例）

这篇不是周刊体，而是独立深度调查，写法明显不同：**用数字编号（1–6）分章节，像剥洋葱一样层层递进，把一起技术八卦讲成侦探故事。**

- **第1节·抛悬念+给背景**：先点出"连马斯克都关注"，再交代长期疑云（"自从2024年10月……外界就一直怀疑，它是套壳的中国模型……但苦于找不到证据"），最后引出破解方法，一步步教读者"真相怎么被挖出来"。
- **第2节·亮铁证+戏剧化**：
> "这下炸锅了，明眼人都看出来，这是铁证，**Composer 2 实际上是套壳的 Kimi K2.5**。"
> "可笑的是，事情一爆发，Cursor 第一时间就把漏洞堵上……但是为时已晚，网上传遍了，就连马斯克也发推。"
- **第3节·转向新焦点（是否侵权）**：引入许可证条款和收入数据，把话题从"是不是套壳"推进到"是否违法"。
- **第4节·反问揭动机**：真相澄清后，用一个设问把文章推向更深的分析层：
> "既然如此，为什么它拼命掩盖这个事实……很难吗？"
> "我猜测，**原因跟 Cursor 不断膨胀的估值有关**。"随后用估值时间线（5000万→4亿→26亿→293亿→500亿美元）做论据。
- **第5、6节·拔高到行业判断**：从个案上升到"中国公司也有技术输出"的大结论，并落到给读者的实用建议：
> "我的想法是，大家要对国产大模型有信心，日常工作完全可以放心使用。"

**手法要点**：新闻钩子开场 → 编号递进 → 每节一个小高潮（发现→铁证→侵权→动机→输赢→行业意义）→ 夹叙夹议（客观复述 + "我猜测""我认为""我的想法是"的主观判断）→ 结尾给出可操作立场。

## 9. 结尾方式（3个真实例子）

阮一峰很少用"综上所述"式总结，而偏爱**开放式收尾**：留一个问题、一句展望或一个态度。

**例1·抛出下一个问题（用悬念延续思考）：**
> "那么，一个让人好奇的问题就来了：如果某种冷门语言没有语料，但有一本很详尽的《使用手册》，我们让大模型学习这本手册，它是否就能学会这种冷门语言编程呢？"
> ——《周刊#390：没有语料，大模型就是智障》

**例2·坦承不确定 + 表明倾向（诚恳收尾）：**
> "可能吗？我不知道，感觉还是前一种情况更现实。"
> ——《周刊#391：AI 的贫富分化》

**例3·把话题推到一个更大的类比/警世judgement（升华收尾）：**
> "以后，现实生活恐怕也是这样：每一个陌生人都不可信任，必须假定是恶意骗局。"
> ——《周刊#392：axios 投毒与好莱坞式骗术》

（补充：深度文/测评则用"给读者的建议"收尾，如 Cursor 文的"大家要对国产大模型有信心"、TRAE 文的"使用 Linux 的同学想要尝试，可以去他们的官网下载"。）

## 10. 文末噪音清单（本段出现的"文末不需要信息"模式）

以下模式在每篇中反复出现，属于结构性噪音，构建写作 Skill 时应剔除：

1. **每篇开头元信息块**：`- 文章 ID:` / `- 公众号 ID:` / `- 发布时间:` / `- 原文链接:` / `- 摘要:`
2. **周刊固定开场白**："这里记录每周值得分享的科技内容，周五发布。"
3. **开源/投稿/招聘/合作固定段**："本杂志开源[1]，欢迎投稿[2]。另有《谁在招人》[3]服务……合作请邮件联系[4]（yifeng.ruan@gmail.com[5]）。"
4. **封面图说明**："封面图" + 图片 markdown + 一句配图文字 +（via [6]）
5. **所有图片 markdown 链接**：`![图片](https://mmbiz.qpic.cn/...)`（正文夹杂大量此类，纯配图）
6. **周刊纯罗列板块整块**（本人只写一句导语，主体为条目+投稿人+链接）：
   - `文章`（1、2、3… + [n] +（英文/中文））
   - `工具`（含（@用户名 [n] 投稿））
   - `AI 相关`
   - `资源`
   - `图片`（部分含原创解说，需甄别保留）
   - `文摘`（转述他人文章，非本人观点，需甄别）
   - `言论`（1、2、3… + `-- 出处 [n]`，全部为引用他人）
7. **往年回顾板块**："往年回顾" + 标题 + `[n]（#347）`格式的历史期号索引
8. **结尾标记**："（完）"
9. **References 全块**：`References` 之后所有 `[n]` + 名称 + URL 列表（每篇末尾几十上百行）
10. **投稿人署名**：正文条目里的"（ @用户名 [n] 投稿）"
11. **通知类插话**："（ [通知] 下周五一假期，周刊休息。 ）"

> 甄别提醒：`图片`与`文摘`板块中，若含"我觉得""我认为""这让我想到"等第一人称，则为阮一峰本人评论（高价值，如 #393"经济舱座椅"里的"我觉得，中国高铁可以考虑这种做法"）；纯客观转述则为噪音。`言论`板块一律为他人引用，非本人写作，剔除。
